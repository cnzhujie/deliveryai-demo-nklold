# 需求澄清：夜间模式（Dark Mode）

## 1. 一句话概述

在沸点火锅点单演示应用中增加夜间模式（Dark Mode）切换能力，使所有用户在低光环境下能够获得视觉舒适、减少刺眼的界面体验，同时保持现有浅色主题、老人模式和多语言功能不受影响。

## 2. 背景与目标

### 背景

- 当前应用为单一暖白浅色主题（`rice-100` 米色背景 + `charcoal` 深色文字），在夜间或低光环境下背景过亮、刺眼，影响长时间使用体验。
- 应用已具备老人模式（`useElderlyMode` hook，通过 `localStorage` 持久化 + `document.documentElement.classList` 切换 `elderly` class）和语言切换能力，具备相似的模式切换基础设施。
- 技术栈使用 Tailwind CSS 3.4，颜色类名直接硬编码在组件 JSX 中（如 `bg-rice-100`、`text-charcoal-900`），未使用 CSS 变量或语义 token 层，Tailwind 未配置 `darkMode`。

### 目标

- 用户可一键在浅色模式和夜间模式之间切换，切换后全站页面视觉立即生效。
- 夜间模式选择持久化到 `localStorage`，刷新页面后保持用户上次选择。
- 夜间模式下所有页面（绑定餐桌、欢迎页、菜单点餐、订单履约、结账、服务面板、演示控制台）视觉协调、文字可读。
- 现有浅色主题视觉、老人模式、中英文切换功能保持完全不变。

### 不做

- 不跟随系统 `prefers-color-scheme` 自动切换（首次使用默认浅色模式）。
- 不修改 `server/` 目录。
- 不引入后端 API 调用，所有数据保持前端内存态。
- 不引入额外的 UI 库或设计系统框架。
- 不改动现有业务逻辑、状态机、订单流程。
- 不新增除夜间模式外的其他视觉主题。
- 不引入三态切换（浅色/夜间/跟随系统），仅支持浅色/夜间二态切换。

## 3. 需求详情

### 用户场景

- **谁在用**：所有进入点单应用的用户（门店顾客）。
- **什么场景**：在夜间或低光环境下使用手机/平板浏览菜单、点餐、查看订单、呼叫服务和结账时，浅色背景刺眼、费眼。
- **期望结果**：用户可切换到夜间模式，界面背景转为深色、文字转为浅色，降低屏幕亮度对眼睛的刺激。

### 用户路径

1. 用户进入应用任意页面（绑定餐桌页 / 欢迎页 / 菜单页 / 订单页 / 结账页）。
2. 用户在 TopBar 工具栏找到夜间模式切换按钮（与语言切换、老人模式按钮同排）。
3. 用户点击切换按钮，界面立即平滑过渡（利用现有 250ms 全局过渡动画）到夜间配色。
4. 用户继续正常点餐、查看订单、呼叫服务或结账，所有功能不受影响。
5. 刷新页面或重新进入应用，夜间模式选择被保留，用户无需重新切换。

### 产品规则

- **切换入口**：在 TopBar 现有工具栏中新增夜间模式切换按钮，与语言切换（EN/中）、老人模式按钮并排。
- **默认值**：首次使用默认为浅色模式（localStorage 无记录时默认浅色）。
- **持久化**：夜间模式状态通过 `localStorage` 持久化，key 为 `dark-mode`，值为 `true`/`false`，参照 `useElderlyMode` 模式。`localStorage` 不可用时降级为内存态，不报错不阻塞。
- **生效范围**：夜间模式应用于全站所有页面和组件，包括 TopBar、Banner、菜单卡片、购物车面板、订单视图、结账视图、服务面板、演示控制台、移动端底部导航、悬浮提示。
- **与老人模式共存**：夜间模式与老人模式可同时开启，两者叠加生效（夜间配色 + 放大字号）。
- **与语言切换无关**：夜间模式状态独立于语言切换，互不影响。
- **切换反馈**：切换时显示 Toast 提示，中文为"已切换为夜间模式"/"已切换为日间模式"，英文为"Switched to dark mode"/"Switched to light mode"。

### 状态与反馈

- **成功**：点击切换按钮后，界面在 250ms 内平滑过渡到目标配色方案，Toast 提示当前模式。
- **失败**：`localStorage` 不可用时，切换仅在当前会话生效，不报错，刷新后回到默认浅色模式。
- **空态**：不适用（夜间模式为布尔开关，无空态）。
- **无权限**：不适用（所有用户均可切换）。
- **异常**：`localStorage` 读写异常时静默降级，不影响切换功能本身。
- **保持不变**：老人模式、语言切换、点餐/订单/结账/服务全链路功能逻辑不受夜间模式影响。

### 关键文案

- 夜间模式切换按钮 aria-label：中文"切换至夜间模式"/"切换至日间模式"；英文"Switch to dark mode"/"Switch to light mode"。
- 切换 Toast 提示：中文"已切换为夜间模式"/"已切换为日间模式"；英文"Switched to dark mode"/"Switched to light mode"。
- 图标：使用 `lucide-react` 的 Moon（夜间模式未激活时显示） / Sun（夜间模式已激活时显示）。

### 关键表现要求

- **配色方向**：夜间模式下背景从暖白（`#fbf5ea`）转为深色（基于 `charcoal` 色系的深色变体，如 `charcoal-900`/`charcoal-700`），文字从深色转为浅色（`rice` 色系），确保可读性（WCAG AA 对比度 ≥ 4.5:1）。
- **品牌色保持**：`chili` 红色品牌色在夜间模式下保持可辨识，可适当调亮以适配深色背景。
- **过渡动画**：利用现有全局 250ms `transition` 实现平滑切换，无需额外动画处理。
- **一致性**：所有卡片、弹窗（Radix Dialog）、底部导航栏、悬浮按钮在夜间模式下均有对应的深色样式。

## 4. 约束限制

- **AGENTS.md 更新**：已确认需更新 AGENTS.md，移除"不引入暗色模式或 `dark:` 变体"和"仅需浅色样式"的禁止条款，更新样式约定允许 `dark:` 变体和 `darkMode: 'class'` 配置。
- **实现方式**：采用方案 A——Tailwind `darkMode: 'class'` 配置 + `dark:` 变体。在 `tailwind.config.js` 中新增 `darkMode: 'class'`，在各组件 JSX 中添加 `dark:` 变体。沿用 Tailwind 类名直写模式，不引入 CSS Modules 或 styled-components。
- **兼容要求**：不影响现有 E2E 测试（`e2e/super-spicy.spec.ts`）中基于 class 和文案的断言。
- **性能要求**：夜间模式切换不引入额外渲染开销或首屏延迟。初始化逻辑需在 React 挂载前完成（参照 `index.html` 内联脚本模式），避免闪烁（FOUC）。
- **稳定性要求**：夜间模式与老人模式叠加时，老人模式的高对比度增强规则（`.elderly .text-rice-200/40` 等）需在夜间模式下仍然有效或需要适配。
- **实现边界**：在现有架构内实现，不引入新依赖，不修改协议或底层机制。

## 5. 验收标准

- [主流程] 在应用任意页面下，用户点击 TopBar 中的夜间模式切换按钮后，全站界面应在 250ms 内平滑过渡到深色配色方案（深色背景 + 浅色文字）。
- [持久化] 在夜间模式开启状态下刷新页面或重新进入应用，界面应保持夜间模式，无需用户重新切换。
- [兼容-老人模式] 在夜间模式 + 老人模式同时开启时，界面应同时呈现深色配色和放大字号，两者互不干扰。
- [兼容-语言] 切换夜间模式不影响当前语言设置，切换语言不影响夜间模式状态。
- [边界约束] 夜间模式切换不应影响点餐、订单查看、服务呼叫、结账等任何业务功能链路。
- [异常处理] 当 `localStorage` 不可用时，夜间模式切换仍可在当前会话内生效，不报错、不阻塞。
- [无闪烁] 首次加载页面时，若用户已设置夜间模式，应在 React 挂载前应用深色样式，不出现浅色到深色的闪烁。
- [文案] 切换时 Toast 显示"已切换为夜间模式"/"已切换为日间模式"（中）和"Switched to dark mode"/"Switched to light mode"（英）。
- [构建验证] `npm run build` 和 `npm run lint` 通过，无新增警告或错误。
- [E2E 回归] 现有 `e2e/super-spicy.spec.ts` 用例在夜间模式关闭状态下仍全部通过。
